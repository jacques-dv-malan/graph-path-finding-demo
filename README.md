# Graph & Path Finding Demonstration

A Windows desktop demo that renders a square grid graph, animates a breadth-first search across it,
and draws the resulting path. Its purpose is to illustrate the graph data structure and path finding.

## What the demo shows

- **The graph model** — every cell is a node, every open passage is an edge. Walls are not a
  separate model: a wall is simply the *absence* of an edge between two orthogonal cells.
- **A perfect maze** — the layout is generated by recursive division, by a recursive
  backtracker, by randomized Prim or by Eller's algorithm, picked in the side panel. All four
  produce a spanning tree: every cell is reachable from every other cell, and
  `Edges.Count == Nodes.Count - 1` (visible in the read-outs as *Nodes* and *Edges*).
- **BFS in motion** — the search is stepped one move at a time. A move colours in one cell: the
  cell the search reaches turns blue, and the neighbours it reveals turn amber. The cyan line is
  the path found at the end.
- **Why BFS is optimal here** — in a perfect maze the shortest path is the *only* path, so BFS's
  optimality is never confused by a tie-break between equally short routes.

## Requirements

- Windows 10 (21H2 / LTSC / Enterprise) or Windows 11 (23H2+)
- [.NET 10 SDK](https://dotnet.microsoft.com/download) (LTS)

## Run it

```powershell
dotnet run --project GraphPathFindingDemo.App
```

To produce a release build:

```powershell
dotnet build -c Release
```

## Using it

| Control | Effect |
| --- | --- |
| **Layout** | The maze generator: recursive division (boxes and corridors), recursive backtracker (long corridors), randomized Prim (blobby) or Eller (long corridors, row by row). Changing it rebuilds the maze and resets the search. |
| **Width** / **Height** | Grid size, 5–60 per axis. Changing either rebuilds the maze and resets the search. |
| **Seed** | Seed for the layout generator. The same seed always produces the same maze. A new run starts with the current epoch time in seconds. |
| **New Grid** | Builds a new maze from a new seed, which is derived from the current one. |
| **Play** / **Pause** | Runs or freezes the search. |
| **Step** | Advances the search by exactly one move. |
| **Reset** | Returns the *same* maze to its pre-search state so a run can be replayed identically. |
| **Step interval** | Milliseconds between two moves of the search (0–1000, in steps of 50). Lower is faster. The moves are counted in display frames, so the time between two moves only varies by the jitter of the display. |

The read-outs show the node and edge counts, how many cells have been visited, the current
frontier size, the path length in segments, and the status (`idle` / `running` / `done` /
`no path`).

## Solution layout

### `GraphPathFindingDemo.Core` (`net10.0`)

The graph model and the algorithms, with no UI dependencies.

```
GraphPathFindingDemo.Core/
├─ Graph/
│  ├─ GridNode.cs
│  ├─ GridEdge.cs
│  └─ GridGraph.cs
├─ Layout/
│  ├─ ILayoutGenerator.cs
│  ├─ LayoutStyle.cs
│  ├─ RecursiveDivisionLayoutGenerator.cs
│  ├─ RecursiveBacktrackerLayoutGenerator.cs
│  ├─ RandomizedPrimLayoutGenerator.cs
│  └─ EllerLayoutGenerator.cs
├─ Pathfinding/
│  ├─ ISearchAlgorithm.cs
│  ├─ SearchStep.cs
│  ├─ SearchStepKind.cs
│  └─ BreadthFirstSearch.cs
├─ Endpoints/
│  ├─ EndpointMode.cs
│  └─ EndpointSelector.cs
└─ Factories/
   ├─ IGridFactory.cs
   ├─ GridScenario.cs
   └─ GridFactory.cs
```

`GridNode.cs` also holds `GridPoint` — a node owns its coordinate, so the two are inseparable.

### `GraphPathFindingDemo.App` (`net10.0-windows`, WPF)

The view model, the custom-drawn canvas, and the window that composes them.

```
GraphPathFindingDemo.App/
├─ ViewModels/
│  ├─ MainViewModel.cs
│  ├─ RenderState.cs
│  └─ LayoutOption.cs
├─ Controls/
│  └─ GridCanvas.cs
├─ App.xaml
├─ App.xaml.cs
├─ MainWindow.xaml
└─ MainWindow.xaml.cs
```

`MainWindow` is the composition root: it creates the `GridFactory` and the `BreadthFirstSearch` and hands
them to the `MainViewModel`. There is no DI container.

## Extension points

- **Another layout** (randomised DFS, sparse, dense) — implement `ILayoutGenerator` and return a
  `GridGraph` built with `Connect`. A generator names the layout it produces through
  `ILayoutGenerator.Style`; add it to the list the `GridFactory` is built with and it appears in
  the layout picker.
- **Another algorithm** (Dijkstra, A*) — implement `ISearchAlgorithm`. `MainViewModel` already
  takes an `ISearchAlgorithm`, so only the composition root in `MainWindow` changes.
- **The other endpoint modes** — implement the three remaining branches in `EndpointSelector`
  (`FixedRandom`, `RandomFixed`, `RandomRandom`); the enum values already exist and the other three
  throw `NotSupportedException` in v1.
- **Weighted edges** — `GridEdge.Weight` already exists; only the algorithms change.
- **Canvas click interaction** — `GridCanvas` exposes `RenderState` only; a click handler would map
  a pixel to a node via `Graph.NodeAt`.
